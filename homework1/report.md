## 作業一 之 Problem 1: Ackermann Function

## 解題說明

本題要求分別使用遞迴函式與非遞迴函式計算 Ackermann 函數 $A(m,n)$ 的值。Ackermann 函數是一個以兩個正整數 m 和 n 為輸入的特殊遞迴函數，其結果會隨著 m, n 的增大而迅速變大。

### Ackermann 函數定義如下 :
| A(m,n)                 | 條件                  |
|------------------------|----------------------|
| n + 1                  | 當 m = 0             |
| A(m-1, 1)              | 當 n = 0             |
| A(m-1, A(m, n-1))      | 其他的所有可能        |

### 解題策略

1. 遞迴函式:
   按照題目的條件下去寫，讓程式一層一層的叫自己的方式直到符合條件(m==0)，而結束。
2. 非遞迴函式:
   我設定一個足夠大的 s 來模擬遞迴while重複執行加上if判斷所有測資的 m 是否等於 0，其中max = 100000;依需求調整實際大小。

## 程式實作

### 遞迴程式：

```cpp
#include <iostream>
using namespace std;
int a(int m, int n) {
    if (m == 0) return n + 1; //if m=0,n+1
    else if (n == 0) return a(m - 1, 1); //if n=0,A(m-1,n)
    else return a(m - 1, a(m, n - 1)); //otherwise , A(m-1,A(m,n-1))
}
int main() {
    int m, n; 
    cout << "請輸入m和n :";
    cin >> m >> n;
    cout << a(m, n) << endl;
    return 0;
}
```
### 非遞迴程式：

```cpp
#include <iostream>
using namespace std;

int a(int m, int n) {
    // 設定一個足夠大的 s 來模擬遞迴
    const int max = 100000; // 可依需求調整
    int s[max];
    int top = 0;
    s[top++] = m;

    while (top > 0) {
        m = s[--top];
        if (m == 0) {
            n = n + 1;
        }
        else if (n == 0) {
            s[top++] = m - 1;
            n = 1;
        }
        else {
            s[top++] = m - 1;
            s[top++] = m;
            n = n - 1;
        }
    }
    return n;
}
int main() {
    int m, n;
    cout << "請輸入m和n :";
    cin >> m >> n;
    cout << a(m, n) << endl;
    return 0;
}
```

## 效能分析
遞迴函式：
1. 空間複雜度：
   * 當 $m \le 2$ 時：深度為線性，空間複雜度為 $O(n)$。
   * 當 $m = 3$ 時：深度達 $O(2^n)$。
   * 當 $m \ge 4$ 時：空間複雜度超越一般指數級，極易突破作業系統預設的 Stack 限制，造成 **Stack Overflow**。
2. 時間複雜度：
   * $m = 0, 1, 2$：時間複雜度分別為 $O(1)$、 $O(n)$、 $O(n)$。
   * $m = 3$：時間複雜度約為 $O(2^n)$。
   * $m \ge 4$：操作次數遠超計算範圍。例如 $A(4, 1) = 65533$，遞迴呼叫次數即達上億次；計算 $A(4, 2)$ 所需步驟超過運算範圍，計算不可行。
     
非遞迴函式：
1. 空間複雜度：
   * m=3 時，空間複雜度 $O(n)$
   * m=4 時，空間複雜度 $O(2^n)$
   * m≥5 時，空間複雜度超越 O(2^(2^(...2^n)))（n層）
2. 時間複雜度：
   * 對於 m=3，複雜度約 $O(2^n)$
   * m=4，複雜度約 O(2^(2^(...2^n))) （n 層）。實際上，計算 A(4, 2) 就需要幾億次操作。

### 選擇遞迴方法的原因

1. 程式邏輯直觀 :

   遞迴能清楚表達 Ackermann 函數 的核心概念 :

   - 當 𝑚=0時，可以直接回傳 𝑛+1 。

   - 當 m > 0 且 n = 0，回傳 A(m-1, 1)。

   - 當 m > 0 且 n > 0，回傳 A(m-1, A(m, n-1))。

   這三種情況能用 if/else 結構清楚實現，邏輯分明。

2. 遞迴清楚 :

   每次遞迴都根據 m 與 n 的值進行分支，呼叫自身，且每個分支都明確，沒有複雜的前置處理或後續工作。這樣遞迴結構便於追蹤、除錯。
   
**優缺點**

   #### 優點
   - 直觀反映函數本質、程式碼簡潔、易懂

   #### 缺點
   - 呼叫深度極大時容易引發作業系統的 Stack Overflow，且每一次函式調用皆伴隨堆疊的暫存保存的額外開銷，來記憶上一次呼叫完的位址，效能低且不好處理較大的輸入。

## 作業一 之 Problem 2: Powerset

## 解題說明

- 題目要求設計使用遞迴回溯演算法（Recursive Backtracking），來輸出集合S的所有子集合所構成的集合，就是冪集(Power Set *P*(s))。
- 若集合大小 $\vert{}S\vert{} = n$，依組合數學定義，其子集合總數必為 $2^n$（包含空集合 $\emptyset$ 與集合本身）。

例如: 若輸入大小 $n = 3$，輸入集合元素 a, b, c  

輸出: { (),(a),(b),(c), (a,b), (a,c), (b,c), (a,b,c) } 

### 解題策略
1. 二元決策樹模型 (Binary Decision Tree):
   對於集合中的每一個元素 $A[i]$，在建構子集合時僅存在兩種決策：
   - 不選取：跳過當前元素，直接遞迴處理下一個元素 $i+1$。
   - 選取：將 $A[i]$ 推入暫存堆疊中，遞迴探索後續狀態，探索完畢後透過 pop 執行回溯，恢復環境狀態。
2. 手動堆疊與動態配置 (Dynamic Stack Simulation):
   - 不預先建立 $2^n \times n$ 的二維陣列儲存所有子集，改用一維動態陣列 s[] 搭配指標 top 模擬輕量化堆疊。
   - 當遞迴深度達到 $i = n$ 時（抵達決策樹葉節點），直接印出堆疊內現存的元素組合，使空間消耗維持在最小的 $O(n)$。
3. 格式化輸出控制:
   - 傳入布林參考變數 bool& r 作為旗標，為了控制子集合之間的逗號分隔符號，確保最外層集合括號 {} 內部的語法整潔。
## 程式實作

**作業系統/IDE**:
Microsoft Visual Studio Code C/C++

**編譯器**:
g++

```cpp
#include <iostream>
#include <string>

using namespace std;

void push(string s[], int& top, const string& v) {
    s[top++] = v;
}
void pop(int& top) {
    if (top > 0) {
        top--;
    }
}
void powerset(string A[], string s[], int& top, int i, int n, bool& r) {
   
    if (i == n) { // 終止條件：已考慮完全部元素
        if (!r) {
            cout << ", ";
        }
        r = false;

        cout << "(";
        for (int j = 0; j < top; j++) {//印出目前元素,當子集是空集合（top == 0）時，迴圈一次都不會執行
            cout << s[j];
            if (j != top - 1) cout << ", ";
        }
        cout << ")";
        return;
    }
    powerset(A, s, top, i + 1, n, r);// 不選取A[i]分支，繼續遞迴往下探索，直到最後碰到底部（i == n）時才會印出該完整組合
    push(s, top, A[i]);// 選取當前元素 A[i]，使用 push 加入放進s[]
    powerset(A, s, top, i + 1, n, r);
    pop(top); // 使用 pop 將 A[i] 移除，復原狀態s[]變空空
}

int main() {
    int n;
    cout << "請輸入集合大小 n : ";
    cin >> n;

    string* A = new string[n];
    string* s = new string[n];

    int top = 0; //指標存一下

    cout << "請輸入集合元素 : ";
    for (int i = 0; i < n; i++) {
        cin >> A[i];
    }

    cout << "S = {";
    
    bool r = true;

    powerset(A, s, top, 0, n, r);
    
    cout << "}" << endl;

    delete[] A;
    delete[] s;

    return 0;
}
```

## 效能分析

1. 時間複雜度： $$O(n \cdot 2^n)$$
- 遞迴節點總數：  
  演算法對集合中的每個元素皆有「取」與「不取」兩種決策分支，遞迴樹的高度為 $n$。整棵二元樹的總節點數為：
  $$\sum_{k=0}^{n} 2^k = 2^{n+1} - 1 = O(2^n)$$
- 單一葉節點輸出成本：  
  當遞迴抵達終止條件（葉節點 $i = n$）時，程式會執行一個 `for` 迴圈輸出堆疊內長度為 $top$ 的元素。每個子集的平均長度為 $\frac{n}{2}$，最壞情況為長度 $n$（全選），因此單次輸出的平均時間成本為 $O(n)$。
- 綜合總時間：  
  全樹共有 $2^n$ 個葉節點，每個葉節點需花費 $O(n)$ 進行走訪輸出，故整體時間複雜度為：
  $$O(2^n \times n) = O(n \cdot 2^n)$$

2. 空間複雜度： $O(n)$
- 動態記憶體空間：  
  程式僅配置了兩個長度為 $n$ 的動態陣列 `A[]`（輸入資料）與 `s[]`（堆疊暫存），佔用空間為 $O(n)$。
- 系統呼叫堆疊（Call Stack）：  
  遞迴的最大深度等於集合大小 $n$，因此作業系統呼叫堆疊的最大深度維持在 $O(n)$。
- 空間效益評估：  
  本實作採取「**就地回溯、即時輸出**」策略，不預先儲存所有已產生的子集合，也就是邊算邊印，因此免去了龐大的 $O(n \cdot 2^n)$ 二維儲存空間，將輔助空間壓制在最優的線性等級 $O(n)$ 記憶體開銷比較小。

### 結論

1. 狀態復原機制的重要性：
   - 回溯法的核心在於 push 進入選擇分支後，遞迴回去時必須搭配相應的 pop。此舉在這程式中，僅需共用同一條長度為 $n$ 的暫存陣列，極大地壓低了記憶體配置與刪除開銷。
   - 不用一直重複儲存整個空間，複製字串跟刪除空間，先輸出到有結果之後把它收回(pop)，恢復原本的狀態。
     
   > 因為有這一步「復原（pop）」，我的程式才能從頭到尾不需要不斷複製記憶體，速度因此快很多。
2. 組合爆炸與輸出瓶頸：
   隨著集合大小 $n$ 線性增加，冪集數量呈幾何級數 $2^n$ 暴增。當 $n=30$ 時，子集數即突破 10 億個。此時演算法的真正瓶頸不在於遞迴邏輯，而在於標準 I/O（cout）的吞吐量極限以及龐大的總計算時間。$n$ 只要稍微加一點點，算出來的答案量就會像滾雪球一樣失控。
   - $n = 3$ 時，子集有 $2^3 = 8$ 個，眨眼間就印完了。
   - $n = 10$ 時，子集有 $2^{10} = 1,024$ 個，也很輕鬆。
   - 但當 $n = 30$ 時，子集有 $2^{30} \approx 10.7$ 億個！
   > 程式跑很慢不是因為我程式寫得差，而是「數學上答案本來就有 10 億個」，電腦光是把字印出來這件事（I/O 吞吐量）就已經吃不消了。
3. 重複元素的邊界擴充思考：
   本題實作假定集合 $S$ 之輸入元素皆具唯一性（Distinct Elements）。若實務上輸入資料含有重複項（例如 $S = \{a, a, b\}$），現有演算法將會重複輸出一樣的子集合。未來若需處理多重一樣元素的冪集問題，應在回溯前先將陣列排序，並在遍歷同層分支時加入條件過濾（如 if (i > start && A[i] == A[i-1]) continue;），方可確保輸出子集的 "唯一性" 。

## 申論及開發報告

### 選擇遞迴回溯法與動態堆疊的原因

1. 二元決策模型與數學定義精確對應 : 
   - 每個元素只有「要」和「不要」兩種選擇，剛好對應遞迴的兩條路，程式碼無需繁複的迴圈計數器或額外的二進位遮罩轉換，邏輯純粹且便於推導驗證。

2. 記憶體動態配置與狀態共用 :  
  - 整個遞迴共用同一個長度為 $n$ 的記憶體區塊，不用每走一步就新增一個記憶體區塊，有效降低動態記憶體配置（Dynamic Memory Allocation）與釋放（Deallocation）的系統負擔。

3. 解耦儲存與輸出，突破記憶體硬體門檻 : 
   - 把「存資料」跟「印資料」分開，邊算邊印才不會讓記憶體爆掉，節省記憶體。

### 優缺點評估

#### 優點
- 記憶體開銷達到理論最優：輔助空間僅需 $O(n)$，遞迴深度與陣列配置皆隨輸入大小線性增長，極度輕量化。
- 程式結構模組化且易讀：透過簡潔的 `push` 與 `pop`  自定義函式操作管理狀態，相較於呼叫 STL 內部容器更加透明且易於掌握底層行為邏輯。
- 通用性高：不受整數型態的位元長度限制，只要時間允許即可持續運算較大的 $n$。

#### 缺點
- 時間複雜度的固有瓶頸：當總數大時，礙於數學公式讓它算不完，還有電腦光是要把它印出來就又快跑不完了，總運算量將遭遇嚴重的時間瓶頸。
- 缺乏重複元素過濾機制：若使用者輸入的元素包含重複值（例如輸入 `a a b`），現有演算法會生成內容完全相同的多餘子集合。實務上若需處理多重集，需額外引入預先排序將相同元素刪除只留下一個。
